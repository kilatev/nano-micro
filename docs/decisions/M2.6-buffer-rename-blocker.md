# M2.6 — Open-buffer rename blocker

## Evidence

Explorer can rename files through Lua, but Lua has no safe global view of the
open-buffer collection. It therefore cannot reject a destination owned by a
different shared buffer or update every view after a filesystem rename.

## Decision

Add `buffer.Rename(old, new)`: it resolves both paths, rejects an open
destination with a different shared buffer, renames on disk, then rebinds the
shared buffer path, backup ownership, modification time, and path settings.
Lua receives only this operation; Explorer retains its path policy and UI.

Session and LSP hooks remain absent until their milestones.
