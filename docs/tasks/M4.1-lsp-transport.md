# M4.1 — LSP transport and lifecycle

## Outcome

Start one configured language server, exchange framed JSON-RPC messages, and
stop it cleanly with the project.

## Depends on

- Stable project root and plugin process APIs.

## Non-goals

- User-visible LSP features.
- Multiple servers per language.

## Acceptance

- Framing handles partial and combined reads.
- Requests, responses, notifications, errors, cancellation, and shutdown are
  testable independently of a real server.
- Server stderr cannot corrupt protocol input.

## Detailed plan

Define after evaluating the existing Micro LSP plugin implementations.
