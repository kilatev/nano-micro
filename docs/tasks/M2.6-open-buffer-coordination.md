# M2.6 — Open-buffer filesystem coordination

## Outcome

Rename and move operations keep open buffers, tabs, session identity, and LSP
document URIs consistent.

## Depends on

- M2.4 create, rename, and move.
- M2.5 trash-based delete.
- Session and LSP integration points may initially be adapters or no-ops.

## Non-goals

- Implementing full sessions or LSP ahead of their milestones.

## Acceptance

- An open renamed file continues editing and saves to the new path.
- Failure cannot leave two components believing different paths.
- Coordination behavior is covered by state-level tests.

## Detailed plan

First add a state-level regression test for an open file renamed through the
Explorer, then saved. `Buffer.SaveAs` writes buffer contents before it changes
`Path` and `AbsPath`, so it cannot be used to rebind an already-renamed file.
Lua also does not expose the global open-buffer collection. Document that
blocker, then add the smallest generic core operation that atomically rebinds
the shared buffer identity only after the filesystem rename succeeds. Keep
session and LSP adapters as no-ops until their milestones. Cover shared views
of the same buffer and a failed rename.
