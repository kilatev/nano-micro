# M2.3 — Explorer context menu

## Outcome

Right-clicking a tree entry opens a keyboard-accessible context menu whose
available actions match the selected entry.

## Depends on

- M2.2 Git status badges.

## Non-goals

- Implementing the filesystem mutations themselves.
- A general GUI framework beyond the smallest reusable menu primitive.

## Acceptance

- Menu positioning stays within terminal bounds.
- Escape closes without side effects.
- Actions cannot target a stale or different selection.

## Detailed plan

First extend the dock simulation to confirm the remaining plugin boundary:
Micro can route mouse actions to the dock and exposes bottom-line prompts, but
has no positionable menu primitive. Record that concrete blocker before any Go
change. If confirmed, add only a generic application menu overlay exposed to
Lua; it must clamp to the terminal, support mouse plus keyboard navigation,
and close on Escape.

In the workbench plugin, bind right-click without replacing an explicit user
binding, snapshot the clicked Explorer row when opening the menu, and reject a
selection if that snapshot is no longer current. Show only entry-appropriate
future actions; callbacks may report the selected action, but filesystem
mutation remains deferred to M2.4 and M2.5. Cover edge positioning, Escape,
file-versus-directory choices, and stale-row rejection in the existing Go
simulation harness.
