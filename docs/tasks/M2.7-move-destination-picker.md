# M2.7 — Move destination picker

## Outcome

Explorer lets the user select a destination folder from the project tree when
moving a file or directory, without manually typing its path.

## Depends on

- M2.6 open-buffer filesystem coordination.

## Non-goals

- Cross-project moves.
- New filesystem mutation semantics.

## Acceptance

- Move presents project folders as destination choices.
- Selecting a folder moves the selected entry into it using its current name.
- Cancel and stale selections have no side effects.
- Existing destination files remain protected from overwrite.

## Detailed plan

Replace Explorer's text-path Move prompt with the existing application menu.
Build a sorted flat list of project folders, including the project root, and
show project-relative labels. For a moved folder, omit that folder and its
descendants; moving into either is invalid. Capture the tree version with the
selected source and, in the callback, reject stale selections, a vanished
folder, out-of-project paths, and existing destination entries before calling
`buffer.Rename`. Re-render and refresh tab names only after success.

Keep the current rename and filesystem semantics. No core UI or filesystem API
is needed: this is Explorer policy over `ShowMenu` and `buffer.Rename`.

## Tests

- State test: choose a nested destination folder and verify the item moves
  there under its existing basename.
- State test: a stale destination callback and an occupied destination leave
  the source unchanged.
