# M1.3 — Dock blocker decision

## Goal

Decide from prototype evidence whether the sidebar can remain plugin-only or
needs one generic application-level dock primitive in the Go core.

## Depends on

- M1.2 sidebar prototype.

## Work

1. Reproduce each recorded sidebar limitation.
2. Separate polish issues from architectural blockers.
3. Compare a plugin-only workaround with the smallest generic core primitive.
4. Write a short decision record before implementation.
5. If a core change is justified, specify its API and tests as a new task.

## Non-goals

- Implementing Explorer, Search, or Git.
- Redesigning Micro's layout system.
- Feature-specific core APIs.

## Done when

- The decision is evidence-based and documented.
- The next task is either plugin-only hardening or one scoped generic core hook.
- Upstream compatibility impact is explicit.
