# M2.2 — Explorer Git status badges

## Outcome

Explorer decorates changed files and directories using repository status.

## Depends on

- M2.1 read-only tree.

## Non-goals

- Diff rendering.
- Staging.
- Background filesystem watching unless required by measured UX.

## Acceptance

- Modified, staged, untracked, renamed, and deleted paths are distinguishable.
- Paths with spaces or non-ASCII characters are handled safely.
- Refresh behavior is explicit and testable.

## Detailed plan

Keep this in the bundled workbench plugin. Parse one explicit
`git status --porcelain=v1 -z` refresh into a path-to-status map, then add
compact markers while rendering the established M2.1 tree. Test with a small
temporary repository, including spaces and non-ASCII paths. Do not add a
watcher, staging action, or Go API.

## Verified

- The bundled plugin refreshes on dock open and through `workbench-refresh`,
  using `micro/shell.ExecCommand` and repository-root-relative porcelain paths.
- NUL-delimited records preserve spaces and non-ASCII names; rename source
  fields are consumed without becoming duplicate tree rows.
- Exact file `XY` badges, changed-descendant directory markers, and
  non-openable virtual deleted rows render in the existing Explorer tree.
- Non-repositories render without badges. Unexpected failures report through
  the info bar and leave the last valid tree unchanged.
- The workbench simulation and full test/build/version validation pass.
