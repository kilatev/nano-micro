# M1.4 — Generic application dock hook

## Goal

Add the smallest optional, left application dock primitive that a bundled Lua
plugin can populate with a buffer. The dock is one application-owned pane,
shown beside every editor tab rather than inserted into any tab's split tree.

## Depends on

- M1.3 dock blocker decision.

## Required behavior

- A plugin can attach one scratch buffer to the dock and detach it again.
- The visible dock has one configurable width supplied by the attaching
  plugin; no persisted setting or width policy is introduced.
- When attached, every editor tab is laid out to the right of the dock and
  restores its full width when detached.
- The dock is rendered once, persists while switching editor tabs, and receives
  mouse events inside its rectangle before editor-tab dispatch.
- Tab switching, splits, resizing, and keyboard focus continue to operate on
  editor panes; the dock must not become a tab-local split or tab entry.
- The primitive is generic: no feature names or feature-specific state in Go.

## Public plugin surface

- Expose `micro.SetDockBuffer(buf, width)` to attach or replace the dock
  buffer and return its `BufPane` for plugin interaction.
- Expose `micro.ClearDock()` to detach it.
- Width is a positive terminal-cell count. Calls with no dock buffer or a
  non-positive width clear the dock.

## Non-goals

- Right, top, bottom, nested, or multiple docks.
- Persisted dock width, responsive hiding, dock tabs, or dock-specific themes.
- Explorer, Search, Git, session, or LSP behavior.
- Changes to existing split commands or tab semantics.

## Done when

- A simulation test proves a dock buffer remains visible across tab switches,
  reserves the same width for each active editor tab, and restores full width
  after `ClearDock`.
- A mouse test proves dock clicks reach the dock pane and editor clicks still
  reach the active tab pane.
- Existing tab, split, and plugin tests pass with no dock attached.
- `workbench` is updated only enough to use the new API and retains its static
  M1.2 behavior.
